# 双代理协作约束协议（Codex + Claude Code）

生效日期：2026-02-28  
适用范围：`F:\code\eraMaouEx\交互\` 下全部分析与交付文档

## 1. 总则
1. 用户最新指令优先级最高。
2. 本协议用于约束 Codex 与 Claude Code 的统一行为。
3. 所有结论必须可追溯到项目文件；禁止臆测为事实。
4. 发现冲突信息时，必须显式标注“冲突/待确认”。

## 2. 目录与命名规范
1. 主要输出文件命名：`NN_主题名.md`（如 `01_项目入口与主循环.md`）。
2. 阶段性草稿命名：`tmp_主题名.md`，完成后合并或删除。
3. 归档目录：`F:\code\eraMaouEx\交互\归档\YYYY-MM-DD\`。
4. 协作文档统一放在 `F:\code\eraMaouEx\交互\`，不写入其他目录。

## 3. 数据归档逻辑
1. 每个分析 md 顶部必须有元数据块：
```md
---
task_id: <任务ID>
owner: Codex | ClaudeCode
status: draft | in_review | done
source_scope: <读取范围>
updated_at: YYYY-MM-DD HH:mm
---
```
2. 每条关键结论必须带“证据路径”（至少文件路径，可选行号）。
3. 事实与推断分离：
- `事实`：直接来自文件内容。
- `推断`：基于事实的解释，必须明确标注。
4. 修改已发布结论时，不覆盖旧结论，改为“修订记录”追加。
5. 每次任务结束，把最终版复制到当日归档目录。

## 4. 行为逻辑
1. 标准流程：`快速扫描 -> 重点阅读 -> 输出结构化结论 -> 自检`。
2. 自检必须覆盖：
- 是否覆盖任务要求的文件范围；
- 是否有未证实结论；
- 是否有编码异常未说明；
- 是否列出未确认问题（TODO）。
3. 若遇到编码乱码，不得跳过：保留原文片段并给出可能含义。
4. 若任务范围过大，先拆分子任务并按优先级执行（P0 -> P1 -> P2）。
5. 禁止破坏性操作（删除大批文件、覆盖历史产物）除非用户明确要求。

## 5. 交互逻辑（双代理协同）
1. 开始任务前先读取：
- 本协议；
- 本协议第 14 节任务清单；
- 已有同名主题分析结果（若存在）。
2. 交接必须写“交接块”：
```md
## Handoff
- 已完成：
- 未完成：
- 风险点：
- 下一步建议：
```
3. 接手方必须先确认交接块，再继续编辑，避免重复工作。
4. 同一主题文件一次只允许一个代理作为 `owner` 主写，另一方做补充审阅。
5. 审阅意见写入原文件末尾 `## Review Notes`，不单独散落到其他文件。

## 6. 输出格式约束
1. 每份分析 md 至少包含：
- 功能概述
- 关键文件清单
- 流程分析（输入 -> 条件 -> 结果）
- 关键变量/标志位
- 模块调用关系
- TODO / 风险
2. 文件路径使用绝对路径（如 `F:\code\eraMaouEx\ERB\...`）。
3. 用中文写作；术语保持一致，首次出现可中英并列。

## 7. 冲突与升级
1. 出现以下情况必须升级为“待用户确认”：
- 两个来源结论相互矛盾；
- 需要修改协议自身核心规则；
- 需要删除或重写大量历史文档。
2. 升级记录格式：
```md
## Escalation
- 问题：
- 影响范围：
- 候选方案A/B：
- 推荐方案：
```

## 8. 协议变更机制
1. 任何一方可提交协议变更建议。
2. 变更写入本文件末尾 `## Change Log`，记录日期、变更点、原因。
3. 无用户确认时，仅允许增补说明，不改动核心约束条款。

## 9. Windows 编码强制规则（UTF-8）
1. 在 Windows 环境下，所有新建和修改的文档必须使用 `UTF-8` 编码保存。
2. 读取文本时必须显式指定 UTF-8（如 `Get-Content -Encoding UTF8`）。
3. 写入文本时必须显式指定 UTF-8（如 `Set-Content -Encoding UTF8`）。
4. 终端输出前必须设置 UTF-8（如 `[Console]::OutputEncoding=[System.Text.Encoding]::UTF8`）。
5. 禁止依赖系统默认代码页（ANSI/GBK 等）处理协作文档。
6. 若发现乱码，必须立即执行 UTF-8 重读/重写并在文档中记录修复。

## 10. Python 复现功能执行指令（面向 Claude Code）
1. 本阶段目标：使用 Python 基本复现原作核心流程，优先“可运行 + 可验证”，不追求一次性 100% 兼容。
2. 技术约束：
- 实现语言固定为 Python。
- 优先命令行版本（CLI），后续再考虑图形界面。
- 所有新增代码与文档使用 UTF-8。
3. 实施顺序（必须按阶段推进）：
- `P0`：运行骨架（状态容器、时间推进、事件调度、CSV 加载、CLI 入口）。
- `P1`：核心玩法（主菜单、回合/日/月钩子、基础指令执行、存读档）。
- `P2`：扩展系统（商店/售卖、地城、侵略、MOD 开关兼容层）。
4. 目录与产物约束：
- Python 代码统一放在 `F:\code\eraMaouEx\modern-rebuild\` 下（若目录存在则沿用）。
- 每阶段必须产出一个进度文档：`F:\code\eraMaouEx\交互\Python复现_阶段Px.md`。
- 每阶段必须产出一个可执行验证记录：`F:\code\eraMaouEx\交互\Python复现_验收记录.md`（持续追加）。
5. 验收标准（每阶段都必须满足）：
- 至少 1 个可直接执行的入口命令。
- 至少 1 组自动化测试（单元或集成）并记录结果。
- 文档中明确“已支持 / 未支持 / 下一步”。
6. 协作要求：
- Claude Code 实现代码后，Codex 负责抽检结构、路径、编码与可执行性。
- 出现兼容性分歧时，按“最小可运行实现”优先，不阻塞主线推进。
- 若需改动本协议核心条款，必须先走 `Escalation`。
